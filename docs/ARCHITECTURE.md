# Устройство агента и зачем нужен каждый компонент

Принцип: компонент остаётся, только если без него результат заметно хуже или дороже. Число агентов и объём инструкций
сами по себе пользы не дают.

## Общая схема

```
человек ──чат──▶ основной агент (модель среды)
                    │  читает: AGENTS.md → навык этапа → нужный файл knowledge/
                    │  вызывает: python tools/strateg.py …   (или MCP-сервер strateg)
                    ▼
        projects/<имя>/  sources ─▶ evidence ─▶ outputs ─▶ decisions
                           ▲            │           ▲
                 researcher │   concl/impact   critic (отдельный контекст)
                 respondent ┘
        хуки среды: начало сеанса · защита · журнал · расход
```

## Четыре вида знаний — раздельно

| Вид | Где | Почему отдельно |
|---|---|---|
| Постоянные инструкции | `AGENTS.md`, навыки, роли субагентов | короткие правила, которые не должны меняться от задачи к задаче и от текста источников |
| Методика | `knowledge/` | подгружается по шагу, а не целиком: экономит контекст |
| Материалы проекта | `projects/<имя>/sources`, `evidence` | у каждого сведения есть происхождение; проекты не смешиваются |
| Состояние задачи | `projects/<имя>/state` | позволяет продолжить после перерыва и в другой среде |

## Компоненты и их оправдание

| Компонент | Что делает | Что было бы без него | Цена |
|---|---|---|---|
| `AGENTS.md` | рабочий процесс и 12 неизменных правил | каждая среда вела бы себя по-своему | около 3 тыс. токенов в каждом сеансе (оценка по длине текста) |
| Навыки (11) | пошаговая процедура этапа или метода | вся методика в одном длинном промпте | читается только текущий, 350–900 токенов (оценка) |
| `knowledge/` (13 файлов) | экспертная методика: что считать фактом, как строить варианты, как проверять обещания | общие слова вместо критериев | читается по одному файлу на шаг |
| Реестр источников и сведений | тип утверждения, источник, место, период, статус | ссылки «на глаз», смешение фактов и гипотез | несколько команд на источник |
| Выводы с основаниями и `impact` | находит, что затронуто новыми данными | полный пересмотр вручную или устаревшие выводы | одна команда |
| `validate` | формальная проверка без модели | ошибки ловил бы человек при чтении | 0 токенов |
| `data` | воспроизводимые расчёты | модель считала бы в уме и ошибалась | 0 токенов |
| Журнал и `cost` | что сделано и сколько стоило | непрозрачность | ведётся почти автоматически |
| Этапы с выбором человека | четыре точки, где решает человек | агент решал бы сам или спрашивал бы обо всём | четыре паузы на задачу |
| Субагент `researcher` | читает длинные источники на быстрой модели | длинные тексты в контексте основного агента | дешевле сильной модели в разы |
| Субагент `critic` | критика без доступа к рассуждениям автора | самопроверка, склонная к согласию | один вызов сильной модели на этап |
| Субагент `respondent` | роль собеседника без знания гипотез команды | «респондент», подыгрывающий интервьюеру | дёшево; результат — только гипотезы |
| Маршрутизация `route` | класс подзадачи → процесс, уровень модели, инструмент; запоминает исправления | всё делает самая дорогая модель | 0 токенов: правила и примеры |
| Хуки | состояние в начале сеанса, защита, журнал, расход и время; один обработчик на все среды, различается только форма ответа | всё это зависело бы от прилежности модели | около 0,1 с на вызов |
| MCP-сервер | те же инструменты для сред без терминала | агент был бы привязан к shell | 120 строк, без зависимостей |
| `decisions` | ответственные, показатели, сроки, условия пересмотра | решение забывается после отчёта | несколько команд |

Чего сознательно нет: отдельной векторной базы и сервиса поиска (объёмы малы; векторный поиск — необязательная надстройка с файловым кэшем);
оркестратора из многих агентов (три субагента покрывают случаи, где нужен отдельный контекст); внешних зависимостей.

## Маршрутизация

`python tools/strateg.py route pick "описание подзадачи"` относит подзадачу к одному из девяти классов (`config/routing.json`)
и возвращает процесс, уровень модели (`script`, `fast`, `standard`, `strong`) и инструмент.

- Каскад из трёх ступеней: исправления человека и агента → внешняя модель-классификатор, если она подключена и уверена
  не ниже порога `external_accept` → встроенные правила по ключевым словам. Без внешней модели маршрутизация не тратит токены.
- Ошибочный выбор исправляется: `route fix R-003 --cls <класс> --why "…"` — пример сохраняется в `config/routing_examples.jsonl`,
  и похожие задачи дальше идут правильно. Слабый результат — `route escalate`.
- Внешняя специализированная модель подключается через переменную `STRATEG_ROUTER_CMD`. Договор повторяет форму моделей,
  которые выбирают из заданных вариантов: на вход — текст подзадачи и варианты с описаниями, на выход — выбранный вариант,
  вероятности и уверенность. Неуверенный ответ, ошибка, мусор на выходе или отсутствие команды приводят к откату на правила
  с пометкой в журнале маршрутов; это проверено локальной заглушкой `tools/router_stub.py` и входит в самопроверку.
- **Адаптер Jev** — `tools/router_jev.py`. Написан по документации агрегатора AI/ML API (`POST /v1/decisions`, модель
  `typesafe/jev`, вопрос типа `choice`). Подключение: `JEV_API_KEY` в окружении и `STRATEG_ROUTER_CMD=python tools/router_jev.py`.
  Через Electron Hub адаптер проверен с настоящим сервисом 13.11.2026 на пяти подзадачах (см. README).
  Через AI/ML API проверены формат запроса, разбор ответа и поведение при сбоях на локальном сервере-имитации
  (входит в самопроверку); живой вызов этого агрегатора не подтверждён.
  Перед использованием сверьте адрес и поля с актуальной документацией: сторонние описания расходятся в деталях.
- Уровни привязаны к моделям в `config/routing.json` → `tiers`; поменяйте под свою среду.

## Поиск по смыслу

Два уровня. Всегда работает словарный: основа слова, словарь синонимов `knowledge/_synonyms.json`, связи между записями.
Если задана переменная `STRATEG_EMBED_MODEL` (например, `bge-m3` в локальном Ollama), к нему добавляются векторные
представления: итоговый счёт — пополам словарный и векторный. Векторы кэшируются в `.cache/` (не попадает в репозиторий).
Модель недоступна — поиск молча остаётся словарным. Проверено на локальной `bge-m3`; без неё репозиторий работает так же.

## Память без самообмана

- Память — это реестры, а не пересказ чатов. У записи есть тип: сведение с источником, вывод агента, решение человека.
- Вывод агента никогда не становится фактом: `concl add` требует оснований и показывает их силу, поиск подписывает его «вывод агента».
- Устаревшее отзывается командой (`ev retract`, `ev supersede`, `sources retract`), а не стирается; отозванное не попадает
  в поиск и вызывает ошибку проверки, если на него осталась ссылка.
- Свежесть оснований решений проверяется по порогу из `config/policy.json`.

## Устойчивость к сбоям

- Каждое действие с ключом идемпотентности выполняется один раз: повтор останавливается с сообщением «уже выполнено».
- Начатое и не завершённое действие видно в `status` при следующем входе — агент проверяет результат, а не повторяет вслепую.
- Сбой инструмента записывается в журнал (для веб-запросов и субагентов — хуком); дальше одна попытка другим способом, затем пробел.
- Файлы реестров пишутся атомарно: сначала во временный файл, затем замена.
- Внутренняя ошибка хука не блокирует работу агента. Пути в хуках Claude Code заданы от корня проекта: с относительным путём хук переставал запускаться при смене рабочей папки и блокировал все действия — эта ошибка найдена и исправлена при сборке демо.

## Команды CLI

`python tools/strateg.py --help` — полный список. Группы: проект и состояние (`new`, `use`, `status`, `stage`, `ask`,
`answer`, `next`, `handoff`); материалы (`ingest`, `sources`); сведения (`ev`, `concl`, `impact`, `related`, `search`);
расчёты (`data`); маршруты (`route`); результат (`validate`, `report`); решения (`dec`); прозрачность (`log`, `cost`);
окружение (`setup`, `doctor`, `selftest`).
