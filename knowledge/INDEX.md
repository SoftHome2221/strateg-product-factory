# База методических знаний — навигация

Здесь лежит методика: как ставить задачу, исследовать, строить варианты и стратегии. Это не материалы проекта
и не состояние задачи. Файлы меняет только человек.

Не читай всё подряд. Открывай файл, когда дошёл до соответствующего шага, или ищи по смыслу:
`python tools/strateg.py search "как отличить барьер понимания от барьера выбора" --scope kb`.

| Когда | Файл | О чём |
|---|---|---|
| Всегда, перед первой записью сведения | `evidence.md` | типы утверждений, уровни уверенности, свежесть, противоречия, пробелы |
| Этап 1 | `framing.md` | от запроса к решению и вопросу; какие вопросы задавать человеку и какие нет |
| Этап 3 | `research.md` | план от вопросов, меняющих решение; сопоставление источников; когда остановиться |
| Этап 4 | `options.md` | как получить содержательно разные варианты; сильные возражения; сравнение |
| Этап 5 | `product-strategy.md` | аудитория и задача, альтернативы, направление и отказы, экономика |
| Этап 5 | `comm-strategy.md` | ситуация, барьер, сообщение и подтверждение, роль каналов, проверка обещаний |
| Этап 5 | `validation-plan.md` | ожидаемое изменение, сравнение, срок, ограничители, правило решения |
| Этап 7 | `decisions.md` | журнал решений, обязательства, условия пересмотра, устаревание оснований |
| По необходимости | `interviews.md` | гайд интервью, анализ, модельные респонденты и их границы |
| По необходимости | `ux.md` | разбор интерфейсов и путей по тому, что видно |
| По необходимости | `data.md` | проверка показателей, единиц, периодов, пропусков; выбор метода |
| По необходимости | `media.md` | изображения, аудио, видео: что агент умеет и чего не умеет |
| По необходимости | `metrics.md` | словарь показателей цифрового продукта и типичные ловушки |

Связи между файлами: `evidence.md` → используется всеми; `research.md` → `data.md`, `interviews.md`, `ux.md` как методы;
`options.md` → `product-strategy.md` + `comm-strategy.md` → `validation-plan.md` → `decisions.md`.

`_synonyms.json` — группы слов, которые поиск считает близкими по смыслу (удержание ≈ retention ≈ отток).
Дополняйте его терминами своей команды.
