# Этап 5. Стратегия

Методика: `knowledge/product-strategy.md`, `knowledge/comm-strategy.md`, `knowledge/validation-plan.md`.

## Шаги

1. `stage start strategy` создаёт `outputs/04-strategy.md`. Основа — выбранный вариант с поправками человека.
2. **Продуктовая стратегия** (раздел 1): аудитория и её задача → альтернативы пользователя, включая «ничего не делать» →
   2–4 ставки направления → осознанные отказы с причинами и условием возврата → экономика: польза → доход → затраты →
   «что должно быть правдой, чтобы сошлось». Числа — со ссылкой `[E-…]` или пометкой «допущение».
3. **Коммуникационная стратегия** (раздел 2) — после продуктовой и на её основании: та же аудитория и ситуация контакта →
   один барьер (понимания или выбора) → ключевое сообщение и подтверждение → роль каждого канала с показателем.
4. **Соответствие обещаний продукту** (2.5): выпиши каждое обещание, явное и подразумеваемое, и чем оно подтверждается.
   Статус только «есть» или «в плане (срок)». Обещание со статусом «нет» убирается — или возвращаемся к продукту.
5. **План проверки** (раздел 3): по строке на каждое хрупкое допущение — ожидаемое изменение (показатель, с какого значения
   до какого), с чем сравниваем, срок наблюдения, нежелательные последствия с порогом, что делаем при каждом исходе.
   Различимость эффекта проверь расчётом: `data compare --a … --b …`.
6. Разделы 4–5: что может изменить рекомендацию; чего мы по-прежнему не знаем.
7. Раздел 0 «Решение в одном абзаце» напиши последним.
8. **Согласованность** — проверь сам по списку: аудитория одна в обеих стратегиях; сообщение = отличие из 1.3 словами
   аудитории; каждое обещание есть в 2.5; отказы не нарушены коммуникацией; каждое допущение экономики есть в плане проверки.
9. `validate strategy` → исправь ошибки и разберись с замечаниями. `stage done strategy`, затем `stage start review`.

## Готово, когда

- `validate strategy` без ошибок; обе стратегии говорят об одной аудитории;
- нет обещаний без подтверждения; у плана проверки заполнены все четыре обязательных поля.

## Не делай

- Не пиши стратегию уверенным тоном там, где основания — гипотезы.
- Не добавляй каналы и функции «на всякий случай»: каждый элемент отвечает на барьер или ставку.
- Не пропускай отказы.
