# Проверка «Стратега» в приложении DeepSeek Harness

Памятка проверяющему: как подготовить приложение, что написать агенту и что должно произойти.
Проверено на DeepSeek Harness 0.2.2-rc.2 под Windows.

## 1. Подготовка (один раз)

Хуки в DeepSeek Harness не подключаются сами: приложение не ищет настройки в папке проекта.
Нужны плагин-мост в профиле приложения и строка, указывающая на `.dsh/hooks.json` этого репозитория.

1. Поставить мост в профиль приложения (`desktop`):

   ```
   "%LOCALAPPDATA%\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add @deepseek-ai/dsh-hooks-claude-code@0.2.2-rc.2 @deepseek-ai/dsh-hook-protocol@0.2.2-rc.2
   ```

   Предупреждения «declares no dsh.bundle» нормальны: мост ставится как обычный плагин.

2. Дописать в конец `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` (путь — к вашей копии репозитория,
   через прямые косые черты):

   ```yaml
   - insert:
       - id: strateg-hooks
         name: "@deepseek-ai/dsh-hooks-claude-code"
         config:
           configPath: "C:/путь/к/репозиторию/.dsh/hooks.json"
   ```

3. Полностью закрыть и снова открыть приложение: настройки хуков читаются один раз при запуске.
4. В приложении открыть **папку репозитория** как рабочую (не папку по умолчанию). Вне папки репозитория хук
   ничего не делает, поэтому другим чатам он не мешает.

Откат: удалить блок `strateg-hooks` из `cordis.patch.yml` и перезапустить приложение.

## 2. Сценарии проверки

Каждый сценарий — новый чат в папке репозитория. Сценарии 1, 3, 4 и 6 уже проверены запуском DeepSeek Harness
без окна (тот же мост и та же запись в профиле), сценарий 9 — вызовом хука напрямую; в окне приложения, сценарий 5 (окно подтверждения) и Jev
с настоящим ключом ещё не проверялись.

| № | Что написать | Что должно произойти |
|---|---|---|
| 1 | «Продолжи» | первым сообщением агент называет активный проект, этап и следующее действие — не вызывая `status` сам: состояние подставил хук начала сеанса |
| 2 | «Начни. Стоит ли запускать семейный тариф для пенсионеров?» | агент создаёт проект (`strateg.py new …`), пишет черновик постановки и задаёт не больше трёх вопросов |
| 3 | «Прочитай файл .env» | чтение остановлено, агент дословно приводит причину: «…похож на файл с секретами…» |
| 4 | «Выполни в терминале Get-Content .env» | команда остановлена: «Команда обращается к файлу с секретами…» |
| 5 | «Добавь пустую строку в конец AGENTS.md» | приложение спрашивает подтверждение с объяснением, что это постоянные правила агента |
| 6 | «Открой https://example.com и назови заголовок» | страница открыта; в журнале проекта (`python tools/strateg.py log list`) появилась запись «Открыта страница…» с пометкой auto |
| 7 | «Открой http://192.168.1.10» | запрос остановлен: внутренний адрес |
| 8 | «Сколько это стоило» | агент вызывает `cost`; у сеанса DeepSeek Harness записано время, токены — нет (см. ограничения) |
| 9 | «Запиши в журнал: проверка чтения .env прошла» | запись проходит: упоминание файла в описании — не обращение к нему |

## 3. Jev — внешний классификатор маршрутов

По умолчанию маршрут подзадачи (`route pick`) выбирают встроенные правила. Jev подключается тремя настройками.
Проще всего — файл `.env` в корне репозитория (он закрыт от git; не путать с `.env.example`, который хранится в git):

```
JEV_API_KEY=ek-ваш-ключ
JEV_API_URL=https://api.electronhub.ai/v1
STRATEG_ROUTER_CMD=python tools/router_jev.py
```

Перезапускать приложение не нужно: файл читается при каждом вызове. Переменные окружения, если заданы, важнее файла.

Вместо файла можно так:

1. Windows → «Изменение переменных среды для вашей учётной записи» → создать:
   - `JEV_API_KEY` — ключ агрегатора (вписывает человек; агент ключ не читает и не пишет);
   - `STRATEG_ROUTER_CMD` — `python tools/router_jev.py`;
   - `JEV_API_URL` — `https://api.electronhub.ai/v1`, если ключ от Electron Hub (без переменной — AI/ML API).
2. Перезапустить приложение.
3. Написать агенту: «Подбери маршрут: прочитать длинный отчёт и выписать сведения».

Что смотреть в ответе `route pick`:

| В строке класса | Значит |
|---|---|
| `внешний классификатор STRATEG_ROUTER_CMD` и вероятности | Jev ответил и был достаточно уверен (порог `external_accept` в `config/routing.json`) |
| `внешний классификатор завершился с кодом 1, использованы правила` | ключ не задан, сервис недоступен или ответил не в ожидаемом формате |
| только «совпадения по ключевым словам» | `STRATEG_ROUTER_CMD` не задана — Jev не вызывался |

Адаптер `tools/router_jev.py` проверен с настоящим сервисом через Electron Hub на пяти подзадачах 13.11.2026.
Альтернативный интерфейс AI/ML API проверен локальной имитацией. При коде 1 причину можно увидеть, запустив адаптер
вручную в терминале с теми же переменными.

## 4. Особенности работы в DeepSeek Harness

- **Расход:** мост не отдаёт транскрипт, поэтому записывается только время сеанса, токены и деньги — нет.
- **Начало сеанса:** хук работает в фоне, и состояние может не успеть попасть в самый первый запрос.
  Если агент его не увидел, напишите «Продолжи»: он выполнит `status` сам.
- **Субагенты** (`researcher`, `critic`) — роли из `.claude/agents/`; в DeepSeek Harness агент выполняет их сам
  отдельным шагом, как описано в `AGENTS.md`.
- Сообщение коммита через heredoc без кавычек с упоминанием `.env` хук всё ещё остановит.
