Автор и владелец репозитория: [SoftHome2221](https://github.com/SoftHome2221).

сохранить основания решения и продолжить работу после перерыва.

## Запуск

Нужны Python 3.9+ и среда с агентом, доступом к файлам и терминалу. Запустите из корня:

```bash
python tools/strateg.py setup
python tools/strateg.py selftest
python tools/strateg.py use family-cloud
python tools/strateg.py status
```

На macOS/Linux используйте `python3`, если команды `python` нет. Эти ОС ещё не проверены.
После настройки откройте папку в среде агента и напишите «Продолжи». Для своей задачи напишите «Начни» и запрос.
Модель и веб-поиск предоставляет выбранная среда; самому репозиторию ключи не нужны.

## Полное руководство

Ниже сохранено подробное руководство и история проверок.

ИИ-агент, который ведёт руководителя цифрового продукта от размытого запроса («падает удержание», «кому продавать»,
«что сказать аудитории») до обоснованной продуктовой и коммуникационной стратегии — и сопровождает решение после того,
как оно принято.

Это не программа и не автономный сервис, а папка с инструкциями, методикой и инструментами. Её открывают в среде
с ИИ-агентом и работают в чате. Целиком проверено в Claude Code; в Codex проверено продолжение готового проекта;
в DeepSeek Harness проверены хуки (подстановка состояния, запреты, журнал, время);
в Cursor проверены MCP, события хуков, защита, доставка контекста и автоматический журнал; состав проверок каждой среды —
см. раздел «Перенос в другую среду».

## Быстрый старт

Нужен Python 3.9 или новее. Внешних пакетов и ключей не требуется.

```bash
python tools/strateg.py setup
```

Команда проверит окружение и подставит в хуки и MCP ту команду Python, которая есть в системе (`python` или `python3`).

```bash
python tools/strateg.py selftest
```

Сквозная самопроверка инструментов без модели, около пяти секунд.

Затем откройте папку в своей среде и напишите в чате **«Начни»** и свой запрос — или **«Продолжи»**, чтобы посмотреть готовый пример.

## Как с ним работать

Вы пишете в чат обычными словами. Агент сам вызывает инструменты и останавливается там, где решать должны вы.

| Вы пишете | Что происходит |
|---|---|
| «Начни» и запрос | агент создаёт проект и задаёт до трёх уточняющих вопросов |
| «Продолжи» | продолжает с сохранённого места, в том числе в новом чате и в другой среде |
| «Статус» / «Что ты сделал» | этап, выполненные действия, что требует внимания |
| «Сколько это стоило» | токены, деньги, время, включая ваше |
| «Стоп» | сохраняет записку «где остановились» |
| «Исправь …» | правит результат и показывает, какие выводы это затронуло |
| «Появились новые данные» | находит затронутые выводы и решения, предлагает пересмотр |
| «Что решать сейчас» | просроченные обязательства, наступившие проверки, устаревшие основания |

Путь состоит из семи этапов; на четырёх из них агент ждёт вашего решения:

1. **Постановка** — вопрос, решение, критерий, ограничения, данные. *Вы подтверждаете.*
2. **Сбор материалов** — документы, таблицы, сайты с сохранением происхождения.
3. **Исследование** — план от вопросов, меняющих решение; картина ситуации с пробелами. *Вы говорите «достаточно» или «копать дальше».*
4. **Варианты** — не меньше трёх, включая «оставить как есть» и «закрыть», с сильными возражениями. *Вы выбираете.*
5. **Стратегия** — продуктовая, коммуникационная, план проверки.
6. **Проверка и отчёт** — формальная проверка скриптом, независимая критика, отчёт с приложениями и расходами. *Вы принимаете.*
7. **Сопровождение** — решения, ответственные, сроки, условия пересмотра, обновление выводов при новых данных.

## Готовый пример

`projects/demo-shield/` — пройденный путь для вымышленного продукта «Щит для близких» (защита пожилых родителей
от телефонных мошенников). Продукт и его внутренние данные придуманы и сгенерированы скриптом; сведения о рынке
взяты из открытых источников, включая обзор Банка России.

Начать чтение стоит с `projects/demo-shield/outputs/report.md`. Посмотреть состояние:

```bash
python tools/strateg.py use demo-shield
```

Что видно в примере:

- «падение удержания» оказывается эффектом смены состава пользователей, а не ухудшения продукта (расчёты в `analysis/`);
- факты, гипотезы и ответы двух модельных респондентов разведены и помечены;
- сайт ВЦИОМ не открылся — сбой записан в журнал, а данные остались пробелом;
- независимый критик в отдельном контексте нашёл восемь слабых мест, включая пороги остановки, пропускавшие убыточный
  исход; стратегия переписана (версия 2), два сведения заменены уточнёнными, один вывод отозван;
- решение записано с ответственным, показателем, датой проверки, условиями пересмотра и четырьмя обязательствами;
- два экрана подключения разобраны по скриншотам (`outputs/ux-review.md`): наблюдения привязаны к месту на экране,
  последствия записаны гипотезами. Экраны — учебный макет, свёрстанный по тексту материала, а не реальный интерфейс.

Оговорки: решения руководителя на развилках в примере принимал автор примера, и это везде помечено словом «ДЕМО».
Расход моделей измерен не полностью: в журнал внесены только вызовы субагентов (около 0,46 $ по ценам из
`config/prices.json`), работа основного агента шла в одном сеансе с разработкой репозитория и отдельно не считалась.

## Что агент гарантирует, а не обещает

Эти правила проверяет скрипт, а не добросовестность модели:

- факт нельзя записать без источника и места в нём; ответ модельного респондента нельзя записать фактом;
- этап не закрывается с незаполненным результатом, формальными ошибками или без записанного решения человека;
- вариантов меньше трёх, нет «оставить как есть» или «закрыть», у варианта нет возражений — ошибка;
- обещание в коммуникации без подтверждения в продукте — ошибка;
- ссылка на отозванное сведение — ошибка; отзыв сведения помечает зависимые выводы и решения;
- повторная загрузка того же источника и повтор действия с тем же ключом не выполняются;
- внутренние адреса и файлы с секретами недоступны; фразы-команды в источниках помечаются как данные.

## Стоимость и время

`python tools/strateg.py cost` показывает расходы по проекту: токены и деньги по моделям, время сеансов, время человека.
В Claude Code и Codex расход считается хуком по транскрипту сеанса; в остальных средах хук измеряет только время,
а токены агент вносит по счётчику среды (см. «Хуки в любой среде»).
Цены моделей лежат в `config/prices.json` — сверьте их со страницей своего провайдера.

**Измеренный пример.** Проект `projects/family-cloud/` («Кому продавать семейную подписку на облачное хранилище?»)
пройден человеком в отдельном чате Claude Code от запроса до записанного решения, все семь этапов:
4,03 $ и около 19 минут по транскрипту сеанса. Из них 4,01 $ — Claude Opus 5.5 (основной агент и критик) и 0,02 $ —
Claude Haiku 5.5 (поиск по источникам). Загружено 11 источников, записано 29 сведений, два сбоя загрузки записаны в журнал.
Время человека на ответы в журнал не внесено. Это один прогон на одной задаче, а не средняя оценка.

Расход демо `demo-shield` отдельно не выделен: он записан вместе с сеансом, в котором разрабатывался сам репозиторий.

Сеанс разработки репозитория в расход проекта не попадает, если запустить среду с переменной `STRATEG_DEV=1`
(защита при этом работает, журнал и расход не пишутся). Сеанс, уже записанный в проект по ошибке, убирается командой
`python tools/strateg.py cost --exclude <id сеанса> --why "..."`: запись переносится в `state/sessions_excluded.jsonl`
и видна в отчёте о расходах; повторно ни расход, ни действия этого сеанса не запишутся ни в один проект.

Как агент экономит: расчёты выполняет скрипт без модели; длинные источники читает субагент на быстрой модели;
критика идёт в отдельном контексте на сильной модели; план исследования отсекает вопросы, не меняющие решение.

14.11.2026 добавлено парное сравнение на одной модели Codex (`gpt-6.1-sol`): обычный чат и агент получили одинаковые
материалы и подготовили стратегию для утверждённого направления family-cloud. Время — 2:14 против 5:31;
формальная доля строк с опорой в финальных ответах — 27% против 40%. ИИ-сверка подтвердила по пять выбранных утверждений
у каждого. Чат силён в содержании, агент — в явной экономике и воспроизводимых проверках; однозначного превосходства
агента не установлено [E-030], [E-031], [E-032], [C-005] (реестры family-cloud).
Это один этап на готовом исследовании, не полный цикл с нуля. Прежние неравные сравнения с Claude Haiku и локальной
моделью сохранены отдельно в том же [отчёте сравнения](benchmarks/README.md). Слепой оценки двумя людьми и сравнения
с аналитиком вручную пока нет.

Узкая польза рабочего процесса дополнительно проверена в отдельной копии: отзыв основания помечает зависимые
вывод и решение, старые ссылки отклоняются валидацией, состояние видно новому процессу, расчёт повторяется
с тем же результатом [E-034], [C-006] (family-cloud). Это функциональные проверки, а не доказательство общего
превосходства рекомендаций.

## Данные и безопасность

- Только открытые источники и материалы, которые дал человек. Режим `strict` ограничивает сайты списком доменов проекта.
- Секреты в репозитории не хранятся: `.env` закрыт в `.gitignore`, агент его не читает и не правит (хук запрещает);
  скрипты берут из него только известные настройки (`STRATEG_ROUTER_CMD`, `JEV_*`, `STRATEG_EMBED_MODEL`) и никуда
  их не выводят. `doctor` ищет ключи в файлах репозитория.
- Текст источников — данные: команды из них не исполняются и правил агента не меняют.
- Правка инструкций, методики и инструментов агентом требует подтверждения человека (в Claude Code — хук).
- Реальные интервью — только с согласия и обезличенные; `doctor` ищет телефоны и почту в записях.

### Хуки в любой среде

Обработчик один: `python tools/strateg.py hook <среда> <событие>`, данные события — JSON на stdin.
Он делает четыре вещи: в начале сеанса подставляет состояние проекта; перед действием не пускает к секретам,
внутренним адресам и правке правил агента; после действия пишет веб-запросы, субагентов и сбои в журнал;
в конце ответа считает расход и время сеанса.

| Среда | Файл | Форма ответа | Расход и время |
|---|---|---|---|
| Claude Code | `.claude/settings.json` | формат Claude Code | токены, деньги и время — по транскрипту; проверено |
| Codex | `.codex/hooks.json` | общий договор | токены и время — по транскрипту Codex; цены моделей OpenAI добавьте в `config/prices.json` |
| Cursor | `.cursor/hooks.json` | формат Cursor | только время сеанса; токены Cursor хуку не отдаёт |
| DeepSeek Harness | `.dsh/hooks.json` через плагин-мост `@deepseek-ai/dsh-hooks-claude-code`; подключение — `.dsh/hooks.patch.yml` (командная строка) или запись в профиле приложения, см. [docs/CHECK-DEEPSEEK.md](docs/CHECK-DEEPSEEK.md) | JSON формата Claude Code с кодом 0 (PowerShell сводит код 2 к 1, обычный текст начала сеанса мост не берёт) | только время сеанса: транскрипт мост не отдаёт; проверено на 0.2.2-rc.2 — состояние, запреты, журнал, время |
| Любая другая | свой файл хуков, среда `generic` | общий договор | только время сеанса |

Общий договор: разрешение — пустой ответ и код 0; запрет — причина в stderr и код 2; контекст начала сеанса —
обычный текст в stdout. Названия полей у сред разные (`tool_name`/`toolName`, `tool_input`/`arguments`,
`session_id`/`conversation_id`, команда строкой или списком, правка заплаткой) — обработчик приводит их к одному виду.
В общем договоре нет ответа «спросить человека», поэтому правка правил агента там запрещается целиком;
для разработки создайте пустой файл `.maintainer` в корне.

Где среда не отдаёт счётчик токенов, в `cost` попадает только измеренное время, а строка расхода честно помечена
«только время» — токены не выдумываются; внесите их из счётчика среды командой `log add … --tokens-in --tokens-out`.

Команда в `.codex/hooks.json` сама находит корень репозитория и вне его молча ничего не делает: хук не может
заблокировать работу из-за неверной рабочей папки.

Где нет хуков, субагентов или навыков, агент действует по таблице «Если чего-то нет в твоей среде» из `AGENTS.md`.

## Условия использования

- Для аудио и видео агент использует расшифровку и просмотренные кадры; автоматический разбор непрерывного потока не заявляется.
  В демо есть аудио с синтезированным голосом и короткая запись отдельного тестового окна с текстом экрана и ключевыми кадрами.
  Для видео проверены декодирование, запрет факта без расшифровки и загрузка после её добавления; кадры извлечены FFmpeg
  и просмотрены. Это не проверка реального интервью или распознавания речи. [Видео и протокол](benchmarks/README.md#проверка-видео)
  [E-033] (family-cloud), [E-041] (demo-shield).
- Внешний классификатор Jev (`tools/router_jev.py`) проверен с настоящим сервисом 13.11.2026 через Electron Hub:
  пять подзадач, все отнесены к ожидаемому классу (три однозначные — с уверенностью 1,0; сравнение цен по сайтам —
  «поиск» с уверенностью 0,71; сообщение для аудитории — «синтез», 0,98). Это пять запросов, а не замер точности.
  Через AI/ML API адаптер проверен только на локальной имитации.
- Сайты, которые строятся скриптами или отказывают автоматическим запросам, скриптом не загружаются; агент пробует
  веб-инструмент среды, затем записывает пробел.
- Поиск «по смыслу» по умолчанию — основа слова, словарь синонимов и связи между записями. Векторный поиск включается
  отдельно и требует локальной модели (`STRATEG_EMBED_MODEL`, например `bge-m3` в Ollama). На десяти перефразированных
  запросах он дал 7 попаданий против 5 у словарного, но работает на порядок медленнее.
- Формальная проверка контролирует опору утверждений; содержательную оценку дополняют критик и человек.
- Полный рабочий путь с реальным выбором человека проверен в Claude Code на Windows. В Cursor и DeepSeek Harness проверены ключевые интеграции; учебный процесс через Cursor и Codex завершён по всем семи этапам [E-035], [E-044]–[E-048].
  В прочих средах, а также на macOS и Linux запуск не проверен.
