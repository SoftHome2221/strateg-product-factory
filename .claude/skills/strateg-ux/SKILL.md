# Анализ интерфейсов и путей

Методика: `knowledge/ux.md`, границы — `knowledge/media.md`.

## Шаги

1. Загрузи материалы по порядку шагов: `ingest <файл> --kind screenshot --title "Шаг 2. Выбор тарифа"`.
2. Открой каждое изображение и запиши в `sources/text/S-….md` описание: только видимое (элементы, тексты, расположение).
   Неразборчивое — «не читается». Не видишь изображений — скажи человеку и попроси описание.
3. По каждому экрану пройди список: задача экрана → иерархия → главное действие → текст → нагрузка → доверие → состояния.
4. По пути: шаги, поля, решения, переходы; места, где обещание не совпадает со следующим шагом или польза показана после оплаты.
5. Запиши наблюдения фактами с местом: `ev add --type fact --source S-… --loc "экран 3, блок цены" --quote "видимый текст" --claim "…"`.
   Последствия для поведения — гипотезами с указанием, чем проверить.
6. Если есть данные воронки — сопоставь через `strateg-data`. Без данных порядок важности проблем — гипотеза.
7. Результат — таблица «Шаг · Что видно [E-…] · Возможное последствие (гипотеза) · Чем проверить» в `outputs/ux-review.md`
   или в картине ситуации.

## Не делай

- Не достраивай экраны, которых нет в материалах.
- Не приписывай пользователям чувства без интервью или отзывов.
- Не оценивай вкус; не ссылайся на «лучшие практики» как на факт о продукте.
