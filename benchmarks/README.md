# Сравнение с исходным способом

## Состояние

14.11.2026 добавлен парный прогон на одной модели Codex: обычный чат и агент готовили стратегию для уже выбранного D
по одинаковому исследованию family-cloud. Это сравнение этапа подготовки стратегии, а не полного цикла с нуля [E-030].
Ни слепой оценки двумя людьми, ни сравнения с аналитиком вручную пока нет. Выборочная сверка источников и отдельная критика ИИ
выполнены; их нельзя выдавать за человеческую оценку [E-032]. Записи E/C этого раздела относятся к проекту family-cloud.
Ниже сохранены прежние замеры и их ограничения; новые результаты дополняют этот же отчёт.

## Парное сравнение на Codex, 14.11.2026

**Вывод агента:** однозначное превосходство агента этот прогон не установил. Чат быстрее и силён в содержании;
агент даёт более явную экономику, таблицу готовности обещаний и воспроизводимый расчёт. У обоих есть недостатки [C-005].

### Условия

- Оба запуска: Codex CLI 0.167.0-alpha.4.1, `gpt-6.1-sol`, reasoning `medium`, доступный веб-поиск, один допустимый прогон каждого способа [E-030].
- Одинаковые запрос и полные исходные материалы приложены прямо к запросу. Их хэш совпал; принятые постановка,
  исследование и вариант D переданы обоим. Готовая стратегия Claude исключена [E-030].
- «Обычный чат» — приближение через Codex CLI в отдельной папке без правил и методики репозитория.
  Это не интерфейс ChatGPT: стандартные инструкции и инструменты CLI остаются. Агент получает дополнительно методику,
  шаблоны и инструменты в отдельной рабочей копии. Исторические одобрения перенесены как тестовые входы;
  новых решений о продукте тест не принимает [E-030].
- Первичная метрика заранее определена по **полным финальным ответам** обоих. Сохранённый файл стратегии агента
  измерен дополнительно, отдельно от ответа в чате [E-031].
- Первый технический запуск чата не получил доступ к файлам из-за политики команд. Он сохранён в
  `codex-2026-11-14/failed-chat-setup/` и исключён из качества; альтернативный способ доставки одинаковых данных — текст запроса.
  В обоих допустимых запусках применён штатный `approve-for-me`, без отключения защит [E-030].

Кэш — часть входа, а не дополнительные токены. Выход агента включает запись файла и последующий полный ответ.

Валидатор считает строки и локальные пометки, **не истинность**. Чат использует обычные ID без квадратных скобок,

Проверка наличия разделов по Markdown-заголовкам также не используется как оценка содержания: оба ответа оформляют часть разделов жирным текстом [E-031].
У агента есть отдельный недостаток доставки: его финальный ответ отличается от проверенного файла и теряет часть локальных пометок [E-031].

### Что подтверждено и что ещё проверить

**Вывод агента:** в этом примере подтверждены отдельные преимущества способа работы — сохранённый документ,
журнал, расчёт и явная связь обещаний с готовностью. Общего превосходства качества или экономии времени не установлено [C-005].

Дополнительно механизмы проверены скриптом `verify_workflow_controls.py` в отдельной копии:
симуляция отзыва E-008 пометила C-001 и зависимое решение, валидация отклонила старые ссылки,
новый процесс увидел необходимость пересмотра, а расчёт из прогона агента воспроизвёлся с тем же результатом.
Живые сведения и продуктовые решения не отзывались [E-034].
Это функциональная проверка инструментов, а не новое парное испытание моделей.
**Вывод агента:** доказана конкретная польза воспроизводимости и сохранения связей; в обычном чате этого прогона
соответствующие артефакты и выполненный расчёт не появились. Общее качество рекомендаций этим не доказано [C-006].

Проверяемая гипотеза следующего замера: эти механизмы полезнее на задачах исправления источника, пересмотра зависимых выводов
и продолжения работы после перерыва. Это нужно измерить на одинаковых заданиях и заранее заданных критериях,
не выбирать удачные для агента ответы задним числом. Слепая оценка людьми и несколько задач остаются пробелами [C-005].

### Проверка видео

Создана запись отдельного тестового окна продолжительностью 13 секунд, без микрофона и звуковой дорожки.
В окне отображены реальные выводы `validate --file` и `data compare`; это контролируемая демонстрация,
не пользовательское интервью. Запись декодирована; кадры на 00:02, 00:06 и 00:10 извлечены и просмотрены [E-033].

В изолированном проекте выполнены негативный и положительный контроли: видео без расшифровки получило пометку
неизвестного содержания, попытка записать факт была отклонена; после VTT и `ingest --refresh` факт по тексту записан.
VTT — экспорт текста экрана, не распознавание речи. Сам `ingest` не извлекает кадры и не анализирует непрерывный видеопоток;
кадры подготовлены внешним FFmpeg [E-033]. Старый локальный источник без расшифровки остаётся отдельной записью;
ссылаться нужно на новую версию с текстом, автоматическое слияние не проверено.

Материал добавлен в существующий demo-shield как S-016 и кадры S-017–S-019; в его существующем отчёте — приложение о видео.
Артефакты: [видео](codex-2026-11-14/video/screen.mp4), [текст экрана](codex-2026-11-14/video/screen.vtt),
[кадр 00:02](codex-2026-11-14/video/frame-1-02s.png), [кадр 00:06](codex-2026-11-14/video/frame-2-06s.png),

## Протокол замера

1. Возьмите три запроса разного типа: «падает показатель», «кому продавать», «что сказать аудитории».
   Для каждого подготовьте одинаковый набор материалов.
2. Три способа: (а) аналитик вручную; (б) обычный чат с той же моделью и теми же материалами, один запрос
   «сделай стратегию» и до трёх уточнений; (в) агент.
3. Для каждого способа запишите: время человека, время до результата, расход моделей.
4. Оцените результат одной линейкой:
   - автоматически: `validate --file` (доля строк с опорой, числа без опоры);
   - вручную, вслепую, двумя оценщиками по шкале 0–2: проверяемость источников, разделение фактов и гипотез, различие
     вариантов, сила возражений, согласованность продукта и коммуникации, пригодность плана проверки;
   - выборочная проверка пяти утверждений по источникам: сколько подтвердилось.
5. Внесите результаты в таблицу ниже вместе с датой, моделью и ограничениями замера.
