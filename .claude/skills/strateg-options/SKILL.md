# Этап 4. Варианты

Методика: `knowledge/options.md`.

## Шаги

1. `stage start options` создаёт `outputs/03-options.md`. Критерии сравнения возьми из постановки.
2. Породи варианты шире, чем нужно (от причин, ограничений, сегментов, заменителей, дешёвых проверок), оставь 3–5.
   Обязательны «A. Оставить как есть» (с прогнозом) и «Z. Закрыть направление».
   Проверка различия: варианты нельзя выполнить одновременно без конфликта за ресурсы.
3. Для каждого варианта заполни: суть; что должно быть правдой; **Факты** со ссылками; **Гипотезы**; **Прогноз**
   с основанием; цена и риски.
4. **Сильные возражения** — субагентом `critic` в отдельном контексте: передай файл вариантов и картину ситуации,
   попроси по 2–3 самых сильных возражения к каждому варианту, включая рекомендуемый. Нет субагентов — выполни роль сам
   отдельным шагом по `.claude/agents/critic.md`. Впиши возражения и ответ на каждое: учтено / принято как риск / отклонено, почему.
5. Таблица сравнения по критериям: в ячейке оценка и причина.
6. Рекомендация: вариант, причина, одно наблюдение, которое изменило бы рекомендацию.
7. `validate options`. Исправь ошибки.
8. **Развилка.** Покажи человеку: варианты по одной строке, таблицу сравнения, рекомендацию. Спроси выбор.
   Запиши его в раздел «Выбор человека» и `stage done options --human "выбран вариант …, поправки: …"`, затем `stage start strategy`.

## Готово, когда

- `validate options` без ошибок; у каждого варианта есть возражения; факты отделены от гипотез и прогнозов;
- человек выбрал вариант.

## Не делай

- Не делай варианты-приманки.
- Не выбирай за человека и не начинай стратегию до его выбора.
- Не ослабляй возражения к варианту, который нравится тебе.
